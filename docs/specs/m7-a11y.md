# Spec: m7-a11y

Status: implemented · Milestone: M7 (security hardening) · Area: `src/.../vimma/ui/`,
`src/browser/themes/shared/vimma/`, `packages/vimma-core/src/{theme,statusbar}.mjs`

## User story

As a screen reader user, or someone who needs readable contrast or no motion, I can use Vimma's
own chrome (the status bar, the overlay, the pickers, panels, prompts, notices and pages) as well
as Firefox's: each part says what it is, focus lands in it when it opens and goes back when it
closes, it speaks when something happens and stays quiet otherwise, and its text reads in both a
dark and a light theme.

## What each component is

| Component                               | Role (name)                                                      | Focus                           |
| --------------------------------------- | ---------------------------------------------------------------- | ------------------------------- |
| Status bar                              | `status` ("Vimma status bar"), `aria-live=off`                   | never takes it; read on demand  |
| Mode and failed-search announcer        | polite live region inside the bar                                | -                               |
| `ctrl+b ?` overlay                      | modal `dialog` ("Key bindings"), `aria-modal`                    | the dialog; back to the opener  |
| Goto, workspace and add-on pickers      | modal `dialog` (title) around a `listbox`                        | the listbox; back to the opener |
| Picker rows                             | `option`, `aria-selected`, the listbox's `aria-activedescendant` | -                               |
| Empty picker or panel ("No add-ons", …) | `role=none` line that the list's `aria-describedby` names        | -                               |
| Side panel                              | `region` ("Side panel") around a `listbox` ("Tabs in …")         | the listbox; back to the opener |
| Bookmarks panel                         | `region` ("Bookmarks") around a `tree` of `treeitem`s            | the tree; back to the opener    |
| Bookmark rows                           | `aria-level`, `aria-expanded` on folders, `aria-selected`        | -                               |
| `:` command line                        | `combobox` ("Command line") with a `listbox` of completions      | the input; back to the opener   |
| Command line error                      | `alert`                                                          | -                               |
| Rename and text prompts                 | non-modal `dialog` named by its question                         | the input; back to the opener   |
| y/N questions                           | `alertdialog` named by the question                              | the input; back to the opener   |
| Notices                                 | polite `status` region; errors in an assertive `alert` region    | never takes it                  |
| Link hint labels                        | `aria-hidden` (the status bar says "hint mode")                  | -                               |
| Find                                    | Firefox's find bar; "Pattern not found: …" once it closes        | Firefox's                       |
| Start page                              | `main`, the logo an image named "Vimma"                          | -                               |
| about:vimma                             | `main`, each section a `region` named by its heading             | -                               |

"Back to the opener": where focus was when it opened, unless the selected tab changed (a row was
picked) or that element is gone; then the selected page. Panels give focus back only when focus
is in them or nowhere: a click into the page keeps it there.

## Decisions

1. **The status bar speaks rarely.** It is `role=status` with `aria-live=off`, so titles and URLs
   are read on demand (a screen reader's "read status bar") and never announced. A polite region
   says a mode once when it changes, except help, command and panel mode, whose focused UI says
   it already (and the way back from them is silent). Hint, visual and resize mode have no
   focused UI, so they and the way back are said. A failed search is said once, after the find
   bar closes. The logic is pure: core `statusAnnouncement`.
2. **aria-activedescendant on the focused list.** Pickers and panels used to focus the dialog or
   the panel box; the active row was then never announced. The list itself now takes focus
   (`tabIndex=-1`: by script only, keys come through VimmaHost).
3. **Notices through persistent live regions.** The popover is `aria-hidden`; its text goes to a
   polite or (errors: a refused URL, an add-on or bookmark failure) an assertive region that is
   always in the tree. The same text again while shown is not announced again.
4. **Readable text tokens.** Colour tokens stay as the palette gives them; text is drawn in
   `--vimma-fg-dim` and new `--vimma-text-*` tokens, which are the palette colour moved toward
   black or white in 5% steps until it reaches 4.5:1 on every surface (`--vimma-bg`,
   `--vimma-bg-dark`, `--vimma-statusbar-bg`, `--vimma-selection`). No text is dimmed with
   opacity. Typed hint letters are underlined instead of faded.
5. **No motion.** Nothing in Vimma's chrome animates or scrolls smoothly, so
   `prefers-reduced-motion` has nothing to turn off; a test keeps it so.

## Contrast (WCAG 2.x AA, 4.5:1), before → after

Tokyo Night (built in): `--vimma-fg-dim` 2.17–2.97:1 → `#9197b2`, ≥ 4.5:1 on every surface;
`--vimma-muted` as text (start page and about:vimma hints) 1.50–2.05:1 → `--vimma-fg-dim`;
`--vimma-cyan` on a selected row 4.26:1 → `--vimma-text-cyan` `#4da2af`; opacity-dimmed text
(picker and panel indices, hosts, hints) → `--vimma-fg-dim`. Every other text token passed.

A light theme (Catppuccin Latte, `tests/contract/theme/light.colors.toml`): every coloured text
token failed somewhere (yellow 1.70–2.31:1, accent 3.18–4.34:1, red 3.52–4.80:1); the
`--vimma-text-*` tokens pass on every surface. Hint labels and mode badges already passed in
both (their text is picked for contrast).

## Tests

- `tests/browser/browser_vimma_a11y.js`: role, name and states of each component through
  `nsIAccessibilityService`; the focused active row; live region politeness; a focus-return test
  per overlay, picker, panel and prompt.
- `packages/vimma-core/test/a11y.test.mjs`: `statusAnnouncement`; every text token on every
  surface in Tokyo Night (built in and Omarchy) and the light theme.
- `tools/test/chrome-css.test.mjs`: the CSS draws text only in checked tokens, dims nothing with
  opacity, animates nothing.
