Release checklist 4.2

Before the release

  • Freeze the branch on Wednesday; only fixes for release blockers after that.
  • Run the load test against staging with the new cache settings.
  • Write down the rollback plan and test it once on staging.
  • Tell the support desk what changes for customers.

Release day

  • Deploy to 5 % of traffic, then 25 %, then everyone, an hour apart.
  • Watch checkout latency and the error rate at each step.
  • Any step over budget: stop, roll back, and write it up in the incident tracker.

After the release

  • Close the milestone and move what slipped to 4.3.
  • Post the release notes and thank everyone who contributed.
