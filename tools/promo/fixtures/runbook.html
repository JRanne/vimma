On-call runbook

You are on call for the checkout service and the payments API from Monday 09:00 to the next Monday 09:00. Keep the pager on, keep a laptop near, and hand over in writing.

When an alert fires

  1. Acknowledge the page within five minutes, then open the incident channel.
  2. Check the deploy log: most alerts start within an hour of a release.
  3. If the last release is the likely cause, start a rollback before you debug.
  4. Post a status line every thirty minutes, even when nothing has changed.

Rolling back

A rollback redeploys the previous build; it never reverts the database. Run deploy checkout --previous and watch the error rate for ten minutes before you call it done.

Schema migrations are forward-only. If a release changed the schema, the database keeps the new columns, and the old code ignores them.

Escalation

Page the secondary after thirty minutes without a cause, and the team lead after an hour. Customer-facing outages also go to the support desk.
